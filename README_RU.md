# ReproCase: установка и работа

ReproCase — самостоятельный проект WERFESTT для подготовки, поиска и воспроизведения тестов численных регрессий. Основной режим работает локально без ключа доступа.

## Локальная проверка и воспроизведение

Склонируйте или скачайте весь репозиторий. Из его корня выполните:

```bash
python3 -I -B judge.py verify
python3 -I -B judge.py demo --language ru
```

Перед импортом модулей проверяются контрольные суммы приложения. Демонстрация повторяет два ранее сохранённых случая на версиях до и после исправления: до исправления ожидается отказ проверяемого условия, после — успешный тест, без ошибок самого проверочного контура. Команда завершается успешно при совпадении всех четырёх ожидаемых исходов. Результат записывается в `review-output/demo.json`.

Сохранённые результаты доступны через [index-ru.html](index-ru.html). Демонстрация не создаёт новых запросов модели. В опубликованной производной копии обезличены исходные пути и идентификаторы сервиса. Численные входы, условия проверки и исходы испытаний сохранены. Команды внутри исторических записей JSON являются данными, а не инструкциями установки.

## Графическое окно

```bash
python3 -I -B judge.py gui --language ru
```

Окно содержит три учебных случая, локальные проверки, подбор входных данных, предпросмотр запроса, выбор темы и переключение русского и английского языков. Сетевые кнопки этой точки входа отключены. Для окна нужны Tkinter и графический сеанс; для повторения тестов и чтения HTML они не требуются.

Переключатель языка находится рядом с выбором темы. Смена языка сохраняет состояние без нового расчёта или запроса модели. Исходные исторические записи сохраняют первоначальный язык. [Описание переключения языка](LOCALIZATION_RU.md).

## Исследование

[Обзор исследования](research/README.md) содержит ссылки на статью, протокол, журналы и переносимые тесты от 7 ноября 2026 года.

```bash
python3 -B research/2026-11-07/verify_public.py --replay
python3 -B research/2026-11-07/test_research.py
```

Первая команда проверяет контрольные суммы и 100 ожидаемых исходов воспроизведения. Вторая выполняет девять существующих проверок плана эксперимента и формирования результатов. Новые ответы модели не генерируются. В исследовательском пакете сохранены собственный снимок исходников и манифесты; дальнейшие изменения приложения не переписывают этот снимок.

Прежний успешный одиночный ответ, незавершённая серия и отдельный локальный ремонт сохранены в `evidence/` со своими исходными статусами. Более позднее завершённое исследование шести ответов находится отдельно в `research/2026-11-07/`.

## Зависимости

| Действие | Требования |
| --- | --- |
| Чтение HTML, статьи и JSON | Браузер, программа просмотра документов или текстовый редактор |
| Воспроизведение тестов приложения и исследования | Python со стандартной библиотекой; ключ и сеть не нужны |
| Графическое окно | Python, Tkinter и графический сеанс |
| Полное повторение исторического поиска | Закреплённые зависимости и совместимый интерпретатор |

Исходные опыты с ответами модели выполнялись в Python 3.14.4 и Hypothesis 6.170.9 на Linux x86_64. Переносимые тесты исследовательского пакета также проверялись в Python 3.12.3. Приложенные пакеты зависимостей предназначены для Python 3.14/Linux x86_64; устанавливать их в другой интерпретатор нельзя.

Для полного исторического сравнения на совместимой платформе:

```bash
python3 -m venv .venv
.venv/bin/python -I -m pip --isolated --disable-pip-version-check install --no-index --no-deps --no-cache-dir --require-hashes -r requirements-pilot.txt
.venv/bin/python -I -B judge.py pilot
```

Установка использует закреплённые файлы из `app/historical_vendor/wheels/` и не обращается к реестру пакетов. Режим `pilot` сравнивает методы поиска на двух исторических дефектах без модели. Режим `synthetic` проверяет программу на явно искусственных ответах. Новые локальные отчёты записываются в `app/outputs/`.

## Подключение модели

Запустите окно с явно разрешённой сетью:

```bash
python3 -I -B judge.py gui --allow-network
```

1. Нажмите **«Подключение модели…»**.
2. Укажите полный адрес сервера, включая путь, например `http://127.0.0.1:8000/v1/chat/completions`, и точный идентификатор запущенной модели. Этот пример предполагает, что сервер уже установлен и запущен вами; ReproCase не устанавливает и не запускает модель.
3. Выберите **«Без ключа»** для сервера без авторизации либо **«Ключ доступа (Bearer)»** для сервера с таким способом авторизации.
4. Выберите поддерживаемый сервером параметр ограничения ответа: `max_tokens` или `max_completion_tokens`. Сохраните настройки.
5. Выберите нужную операцию. Перед отправкой окно покажет адрес, модель, передаваемые данные и предел запросов. Подтвердите этот запуск. При выбранной авторизации ключ запрашивается скрыто и используется только в памяти этого запуска.

Для удалённого сервера требуется HTTPS с действительным сертификатом. Обычный HTTP допускается только для `localhost` или IP-адреса обратной петли, например `127.0.0.1` или `[::1]`. Адреса с логином, паролем, параметрами запроса или фрагментом запрещены. Нерабочие заглушки `.invalid` отклоняются до отправки. Перенаправления не выполняются.

Настройки хранятся в `app/connection_settings.json`, исключённом из Git: только адрес, модель, способ авторизации и имя параметра лимита. Ключ не записывается в этот файл. Образец: `app/connection_settings.example.json`; образец автоматически не активируется. Можно создать рабочий файл вручную по его структуре до открытия окна. Без настроек приложение показывает понятное сообщение и не отправляет запрос. Сохранение настроек и предпросмотр не обращаются к серверу.

### Совместимость и пределы

Сервер должен принимать непотоковые запросы `chat/completions` с `messages`, `tools`, принудительным выбором функции `tool_choice` и `parallel_tool_calls=false`. Ответ: HTTP 200, JSON с тем же идентификатором `model`, ровно один вариант `choices` с `index=0`, `finish_reason="tool_calls"` и одним вызовом ожидаемой функции. Аргументы функции передаются строкой JSON. Дополнительный текст ответа и отказ модели не принимаются; допустимость самого предложения проверяется отдельно локальными правилами. Обычный текстовый чат и другие форматы API автоматически не преобразуются. Если сервер возвращает внутреннее имя модели вместо заданного псевдонима, используйте поддерживаемый им точный идентификатор.

| Операция | Максимум запросов |
| --- | --- |
| Учебный поиск одного случая | 4, до 3 новых проб |
| Сравнение пяти случаев | 20 суммарно, до 4 на случай |
| Подготовка свойства одной задачи | 1 |
| Подготовка свойств двух задач, по три повторения | 6 суммарно, по 1 на сеанс |

В этих режимах сохраняются пределы: до 1024 токенов ответа, 16000 байт тела запроса и 65536 байт ответа; тайм-аут сетевой операции — 30 секунд. Автоматических повторов нет. После ошибки или отмены следующие запросы серии останавливаются. Тариф произвольно выбранного сервера не задан: отчёт показывает известный расход токенов и неизвестную стоимость, без переноса ставок прежней модели. После тайм-аута расход на стороне сервиса может оставаться неизвестным. Эти ограничения не являются денежным лимитом аккаунта.

Для **новой подготовки исторического теста** нужны закреплённые зависимости из раздела выше. Запускайте сетевое окно тем же интерпретатором, например `.venv/bin/python -I -B judge.py gui --allow-network`. Готовность зависимостей проверяется до подтверждения и ввода ключа. Проверяемая точка входа не переключается незаметно на другой интерпретатор.

Команда без `--allow-network` сохраняет блокировку сети. Проверка манифеста действует в обоих режимах. Сохранённые исследовательские результаты и переносимые комплекты используют собственные закреплённые исходники и не требуют нового подключения.

Проверка нового клиента на локальном имитаторе сервера, без настоящей модели и платежей:

```bash
python3 -B -m unittest discover -s tests -v
```

Эта проверка подтверждает передачу настроек, обработку ответов, согласия, отмены, лимиты и локальное воспроизведение. Совместимость с вашим конкретным сервером устанавливается отдельным подтверждённым запуском после настройки.

## Выводы и проверка подлинности

Исследованы два исторических дефекта. Полученные результаты не доказывают общего преимущества модели, экономии времени разработчика, статистической надёжности для произвольных проектов или автономного исправления программ. Отсутствие контрпримера в пределах поиска не доказывает корректность.

`MANIFEST.json` закрепляет активные исходники приложения и документацию. При установке зависимостей проверяются хеши пакетов из `requirements-pilot.txt`; исследовательский пакет имеет собственный `SHA256SUMS.json`. Основная точка входа блокирует сетевые операции и загружает закреплённые модули. Эти проверки выявляют изменения относительно манифеста, но не удостоверяют авторство и не создают универсальную изолированную среду для недоверенного кода.
